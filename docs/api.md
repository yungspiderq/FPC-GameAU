# Протокол и границы гарантий

Реализация сверена с [документацией GameAU](https://gameau.us/api-docs.html?section=catalog) и [OpenAPI 1.4.0](https://gameau.us/openapi.yaml). Релиз подготовлен 14 ноября 2026 года. Загрузчик Cardinal проверен на коммите `c09dd13be25072bb3d5cdbba33d1e0d70e477710`.

Базовый URL: `https://gameau.us/api/v1`. Ключ передаётся только в `Authorization: Bearer`. HTTP-перенаправления запрещены. Запросы последовательные, с интервалом не менее 2,1 секунды; HTTP 429 включает общую паузу. Сырые ошибки API и ключ в журнал не записываются.

Используются `/account`, `/catalog`, `/steamTopup/quote`, `/steamGifts/games/{app_id}`, `/steamGifts/quote`, `/orders/{kind}` и `/orders/status/{id}`. URL из шаблона проверяется на точное совпадение с ожидаемым; произвольные адреса из каталога не вызываются.

Перед платным POST сохраняются точное тело и UUID `Idempotency-Key`. После таймаута новый UUID не генерируется. Для восстановления нужны сверка кабинета и действие администратора; запрос повторяется с прежним UUID и неизменённым телом, включая `maxCharge`.

Ответ создания ещё не означает выдачу. После него плагин запрашивает статус по локальному `order.id`. Успешные статусы из спецификации: `success`, `completed`, `complete`, `delivered`. `processing` опрашивается дальше. `failed`, `refunded`, `cancelled`, `canceled`, `rejected` не приводят к выдаче или новой закупке.

Статус проверяется не чаще одного раза в 10 секунд на заказ; общая очередь может увеличить интервал. Через 30 минут приходит уведомление, интервал для такого заказа увеличивается до минуты. Успешный ответ может содержать только ID и статус — необязательные поля не выдумываются. Если присутствуют тип и безопасная копия запроса, они сверяются с сохранённой покупкой.

Перед закупкой и выдачей перечитывается заказ FunPay: оплата, продавец, покупатель, чат, описание, количество и отсутствие штатной выдачи. Это не общая транзакция с GameAU: одновременный возврат FunPay во время платного запроса требует ручной сверки.

Для новых заказов плагин сопоставляет категорию и описания из оплаченного заказа со своими лотами на FunPay. Если подробное описание содержит отдельную строку `[GAMEAU:ID]`, эта же метка должна присутствовать в редакторе лота и совпадать с его ID. Лот по-прежнему должен подходить по категории и краткому описанию. Если метки нет, плагин сверяет описания. При нескольких совпадениях запрос покупки и автовозврат не отправляются.

Перед отправкой результата сохраняется состояние `delivering`. При перезапуске оно переводится в ручную проверку, потому что сообщение могло дойти до покупателя до потери ответа. Повторная отправка из меню не создаёт новую закупку. Гарантировать ровно одну доставку сообщения при сетевых сбоях невозможно.

Коды сравниваются с сохранёнными кодами других заказов; карты — по содержимому JSON без учёта порядка полей. Эта проверка выявляет буквальные повторы, но не подтверждает работоспособность товара. Для карт/ключей число возвращённых элементов должно совпасть с количеством покупки; спорный результат не помечается выданным.

`maxCharge` ограничивается настройкой продавца и текущим балансом за вычетом резерва; для Steam дополнительно ограничивается суммой расчёта. Исполнение этого предела зависит от GameAU. Плагин не считает отдельные кошельки или другие серверы общей транзакцией и не обещает неизменность остатка при параллельных тратах.

Контроль баланса сохраняет запись о снятии лота **до** изменения FunPay. После неопределённого результата сохранения запись остаётся; повторная проверка сверяет активность. При возврате включаются только лоты, которые плагин действительно пытался снять. Уже неактивные лоты не включаются.

Автовозврат использует штатный `cardinal.account.refund(order_id)` для оплаченного заказа после конкретной подтверждённой причины и до закупки. Исключение для платного POST — документированный `409 PRICE_CHANGED` при первой отправке, когда GameAU гарантирует отсутствие списания. Повтор запроса после таймаута такой гарантии для исходной попытки не даёт.

Плагин записывает состояние `refunding` до вызова FunPay. После перезапуска это состояние переводится в `refund_review`. Сверка по полному статусу `REFUNDED` выполняется чтением заказа. Новый запрос возврата при сверке не отправляется.

Отмена покупок GameAU и пополнение кошелька выполняются вне плагина. `adminProduct` и выдача файлов в этой версии не реализованы. Реальные платежи и возвраты при разработке не выполнялись.
